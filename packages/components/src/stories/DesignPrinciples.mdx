# Design Principles

## 🎯 Accessibility First

Interactive wrappers delegate to **Base UI** where appropriate; static and local extensions use native semantics. The target is applicable
**WCAG 2.2 Level A and AA**, including:

- Correct ARIA attributes and roles
- Keyboard navigation support
- Meaningful names and assistive relationships
- Focus management
- Default-theme contrast, reflow, target sizing and user-controlled motion

Primitives and emulated tests are not proof of full-page conformance. Consumers own localized content, alternative text, custom themes and
valid render composition. Native browser and assistive-technology evaluation remain necessary; see the package's `ACCESSIBILITY.md`.

## 🎨 Design Tokens

We use **OKLCH** color space for perceptually uniform colors:

- Colors stay visually consistent across light and dark themes
- Tokens are CSS custom properties (`--ac-*` prefix)
- Override any token to create custom themes

## 🧩 Composition Over Configuration

Components follow the **compound component** pattern:

```tsx
<Card>
  <CardHeader>
    <CardTitle>Title</CardTitle>
  </CardHeader>
  <CardContent>Content</CardContent>
  <CardFooter>Footer</CardFooter>
</Card>
```

## 🔧 Progressive Enhancement

- Server Components by default
- `"use client"` only when hooks/interactivity needed
- CSS Modules for scoped, predictable styles
- No runtime CSS-in-JS overhead

## 📐 Consistent API

Every component follows these conventions:

- `className` prop for custom styling
- Typed React 19 `ref` props for DOM access and callback cleanup
- Canonical `render` composition, without deprecated child slots or legacy adapters
- `displayName` for debugging
- JSDoc for API documentation
- Co-located tests and stories
